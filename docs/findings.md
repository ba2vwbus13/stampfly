# 原因調査の記録

2026-09-14 から 09-17 にかけて、StampFly の自動ホバリングに取り組んだ際に
遭遇した問題と、その原因・対策の記録。同じ道をたどる人（および将来の自分）
のために、症状・原因・確かめ方・対策を残す。

---

## 1. 前方 ToF が測定のたびにリセットする

**症状** 下向き ToF は正常（30Hz）なのに、前方 ToF は1回測ると止まる。
距離モード（SHORT/MEDIUM/LONG）を変えても同じ。

**原因** USB 給電のみで電圧が 1.7〜2.5V しかなかった。電力不足で ToF が落ちていた。

**対策** バッテリーを接続する（3.8V で正常動作）。

**副作用** ToF がリセットすると I²C アドレスが 0x2A から既定の 0x29 に戻り、
下向き ToF と衝突する。ファームでは 0x2A の応答を監視し、消えたら前方 ToF を
XSHUT で止めて下向きを守るようにした。

---

## 2. 離陸直後に斜めへ突進する

**症状** 離陸した瞬間、機体が斜め方向へ勢いよく飛び去る。PC 制御でも
Atom JoyStick の手動操作でも同じ。

**原因** ジャイロのゼロ点ずれ。起動時の初期化中に機体が動いていると、
その動きを「静止状態」として記憶し、機体は「回っていないのに回っている」と
誤認して傾きを当て続ける。

**確かめ方** 手動操作でも同じ症状が出た（＝ PC 側の制御の問題ではない）。

**対策** 飛ばす直前に**機体のリセットボタン**を押し、初期化中（LEDが紫、約10秒）は
触らない。硬く水平な面に置くこと（カーペットの上だと傾いて置かれる）。

**補足** `c` キー / M5GO の B ボタン長押しで送る AHRS リセットは姿勢推定だけを
初期化する。ジャイロのゼロ点は測り直さないので、この症状には効かない。

---

## 3. 位置制御が逆方向に効く（座標変換の誤り）

**症状** 目標へ戻る指令を出しているのに、機体は離れる方向へ加速する。

**原因** 世界座標の要求を機体座標へ変換する式が「マーカーの X 軸＝機体の右方向」
という暗黙の前提で書かれていた。実際にはマーカーの X 軸は機体の前方向を
指していたため、指令が 90 度ずれていた。

**対策** 変換の前提を明示し、書き直した（`pc/hover.py` の `to_command`）。

```
heading = 機体の前方向が世界の +x となす角度
前ベクトル = (cos h, sin h)
右ベクトル = (sin h, -cos h)
```

単体テスト6件（前後左右の分解、上限処理、符号反転）で検証済み。

---

## 4. 機体が浮くとマーカーを見失う

**症状** 地上では検出できるのに、浮いた瞬間に追跡が途切れる。

**原因** 平らに貼った ArUco マーカーは、カメラから見て寝た角度になると読めない。
機体が上がるほどカメラの見下ろし角が浅くなり、条件が悪化する。

**実測（人工画像24通りで検証）**

| マーカーが寝る角度 | 必要な見かけの大きさ |
|---|---|
| 30度まで | 20px |
| 40度 | 25px |
| 50度 | 40px |
| 60度 | 50px |
| 70度 | **どんな大きさでも不可** |

カメラの見下ろし角 = 90度 − 寝る角度。**カメラの高さ ≧ ホバリング高度 ＋ 水平距離**
が目安になる。

**対策** LED を三角測量する方式に移行（点光源なら傾きの影響を受けない）。

---

## 5. LED 追跡で床より下の位置が出る

**症状** 高さが -0.49m など、床より下の値が頻出。検出率も 53% に低下。

**原因** 床やマットに映った LED の反射を拾い、左右で本物と反射を取り違えて
鏡像の位置を計算していた。

**対策**
- 左右の光点を1つに決め打ちせず、候補すべての組み合わせを評価する
- 三角測量の結果を両画像へ再投影して検算し、対応ミスを捨てる
- 世界座標で床より下になる組み合わせを除外する
- 直前の位置に近い候補を優先する

**効果** ばらつきが 82/16/51mm → 1.2/1.4/6.5mm に改善。

---

## 6. 明るい部屋で LED が埋もれる

**症状** 部屋が明るくなると、ばらつきが 51/45/98mm に悪化。

**原因** 窓（面積39000px）や白い紙（9900px）まで光点として検出されていた。

**対策** 光点の面積に上限（既定300px）を設ける。露出を部屋の明るさに合わせる。
カーテンを閉めて暗くするのがもっとも確実。

**露出の目安** 暗い室内 1200us / 明るい室内 400us。
`oakd/led_stereo.py` を10秒動かし、ばらつき10mm以下になる値を選ぶ。

---

## 7. 静止した光にロックオンして機体を見失う

**症状** 飛行中の16秒間、位置が同じ座標に固定されたままだった。

**原因** 「直前の位置に近い候補を優先する」しくみが災いし、床の上の静止した光に
ロックオンして離れられなくなった。

**対策** 機体が下向き ToF で測った高度（テレメトリ）と照合し、高さの合わない光を
優先しないようにした。ただし**厳しくしすぎると本物を捨てる**（離陸直後は報告値が
先に上がり、実際の機体はまだ床の近くにいる）ため、「捨てる条件」ではなく
「優先する条件」にとどめている。

---

## 8. 飛行中に LED が暗くなる

**症状** 地上では検出できるが、飛行中の検出率が 44% に落ちる。

**原因** 公式ファームは飛行モードで LED の色を変える。

| モード | 色 | 明るさ |
|---|---|---|
| 手動高度モード | 黄色 `0xffff00` | 最大 |
| 自動高度モード（Alt_flag≥1） | `0x331155`（暗い紫） | 最大値の33% |

**確かめ方** 手動高度モードでスロットル0のまま離陸指令を送ると、モーターを
回さずに LED の色だけ変えられる。実測で 30/30 フレーム検出、面積も倍になった。

**対策** 手動高度モードを使い、高さも PC が制御する。

---

## 9. 機体の向きの基準がずれる

**症状** 指令が上限まで出ているのに、機体が加速し続ける。

**原因** 「機体を +x に向けて置く」という人手の手順に依存していた。実測すると
**-90.5度**ずれていた。向きがずれると指令もずれ、離れるほど強く押す暴走になる。

**対策** 離陸前にカラーカメラで機体のマーカーを見て、世界座標での向きを実測し、
機体のジャイロと対応づける（`oakd/led_stereo.py` の `marker_heading`）。

**注意** 機体上面にマーカーを貼ると LED を覆うため、現在はマーカーを外し、
置き方（前を +x に向ける）で合わせている。両立させるなら、LED を避けた位置に
小さく貼る必要がある。

---

## 10. 機体上面のマーカーが LED を覆う

**症状** LED の光点が 3〜11画素しかなく、検出がぎりぎり。動くと消える。

**原因** 向きの測定用に貼った紙が、機体上面の LED を覆っていた。さらに白い紙が
周囲の光を反射し、偽の光点にもなっていた。

**対策** 紙を外す。露出 1200us で**ばらつき 0.9/1.7/4.5mm**（過去最良）。

---

## 11. 機体が浮かない

**症状** スロットルが上限（0.60）まで出ているのに、高さ 0.09m 止まりで床を滑る。

**原因** モーターに電流が流れると電圧が下がる（4.22V → 3.58V）。公式ファームの
式で計算すると、その電圧でホバリングに必要なスティック値は 0.64 で、上限を
超えていた。

**電圧と必要なスロットル**

| 電圧 | 必要なスティック値 |
|---|---|
| 4.1V | 0.30 |
| 3.9V | 0.36 |
| 3.8V | 0.41 |
| 3.7V | 0.49 |
| 3.6V | 0.64 |
| 3.5V | 0.73 |

**対策** 公式ファームの `get_trim_duty()` と同じ式で必要なデューティを求め、
スロットルとデューティの多項式を逆に解いて、電圧から毎回計算する。上限も 0.85 へ。

---

## 12. Tello が試験の途中で勝手に着陸する

**症状** `hover_test.py --seconds 20` の 16秒あたりで ToF が 51→10cm へ落ちて着陸。
そのあとの `land` はすべて `error` を返す（すでに着陸しているため）。

**原因** Tello は**15秒間なにも指令が届かないと自動で着陸する**。ホバリング中の
ループは `get_current_state()` で状態を読むだけで、指令を一つも送っていなかった。
状態の受信は指令にならない。

**対策** ホバリング中も毎回 `send_rc_control(0, 0, 0, 0)` を送る。
`hover_oakd.py` は制御ループで毎回 rc を送るので、この問題は起きない。

**あわせて分かったこと** `h`（気圧基準の高度）は飛行中も 0cm や -40cm を返して
当てにならない。高さの判断は下向き ToF を使う。

---

## 13. 目標の高さに届かないまま時間切れになる

**症状** 40cm を狙ったのに 46cm で止まり、調整の8秒を使い切る。

**原因** 降下の指令を `speed = 誤差` としていたため、誤差6cm では指令 -6 にしか
ならず、機体を動かすには弱すぎた。

**対策** 係数を1.5にし、**最低でも 8cm/s は出す**。許容誤差は 5cm → 3cm、
調整の制限時間は 8秒 → 12秒。

---

## 14. Tello の位置保持に一定のずれが残る

**症状** OAK-D で位置を測って留めると、3〜13秒は平均 3.2cm（最大 4.4cm）で
良好だが、13秒以降は x が **-7.0±1.3cm** に貼り付いたまま戻らない。指令は -8 止まり
（上限 25 には遠い）。

**原因** ばらつきが 1.3cm しかないのに平均が -7cm ずれている。揺れているのではなく、
機体を押し続ける外乱と釣り合う位置で静止している。比例制御だけだと、ずれが小さく
なるほど指令も小さくなるので、この差は自力で詰められない（定常偏差）。

**対策** 積分項を追加（`--ki` 既定 0.35、`--max-i` で上限 10）。溜め込みすぎを
防ぐため上限で頭打ちにし、マーカーを見失っている間は 0 に戻す（復帰した瞬間に
暴れるのを防ぐ）。

**参考値** 映像の遅延 54ms（最大73ms）、カメラ 30fps、最初の3秒は向き測定の
前進から戻る過渡で最大 25cm ずれる（異常ではない）。

---

## 15. 目標のまわりを回り続ける（向きの測定が1回では足りない）

**症状** `--waypoints "0,0 0.3,0 0,0"` で、機体が目標に寄らず**半径20cm・周期7秒の円**を
描き、9秒で半径32cmまで広がって画面外へ出た（平均ずれ23.5cm）。

**原因** 機体の前方向の測定がずれていた。「マーカーとの差」は貼り方で決まる固定値
なのに、成功した回は **+109.6度**、この回は **+64.7度** と45度も違っていた。ずれを直す
向きに押しているつもりで横向きに押すため、いつまでも回り続ける。

8cm 押して始点と終点の差から向きを出していたのが不足だった。機体自身のふらつきは
数cm あるので、8cm の移動では方向が数十度ずれる。

**対策**
- 押す距離を 20cm に増やし、経路の点すべてに直線をあてはめて向きを出す（`--probe-dist`）
- **前と後ろの2回測り、食い違いが 20度を超えたら飛ばさない**（`--probe-agree`）。
  固定値を2回測るのだから一致するはずで、しなければ測定が信用できない
- 離陸前の画面チェックに、測定で動く分（前後 20cm）も含める

**見分け方** ログの位置が目標のまわりを回っていたら向きのずれを疑う。まっすぐ
ずれたまま止まるなら定常偏差（14番）で、原因が違う。

**続き（同日）** 検算を入れた直後の飛行で `173度 食い違っています` が出て中止した
（正しい動作）。前へ16.1cm 動いたあと、後ろへは 4.3cm しか動けていなかった。
前の押しの勢いが残ったまま 0.5秒 で逆向きに切り替えたため、減速中の「まだ前へ
流れている分」が記録に混ざり、向きが前と同じに出て 180度 ひっくり返った。

対策は3つ。押す前に指令0で **2秒** 止まるのを待つ（無指令だと15秒で着陸するので
rc 0 を送り続ける）。始点から **3cm 離れるまでの点は使わない**。目標距離の 6割も
動けなければ **向きを決めずに中止**する。

## 未解決: 指令が上限でも機体が流される

**症状** 高さ 0.17m まで浮くが、指令が上限8度まで出ているのに逆方向へ流れ、
範囲外（0.5m）で自動停止する。

**確認済み** 指令の向きは正しい。追跡も正常（検出率90%）。電圧も十分。

**次の切り分け** ログに機体の実際の傾き（roll/pitch）を記録済み。
- 指令8度 → 実際も8度傾いている ⇒ 姿勢の基準がずれている
- 指令8度 → 実際は傾いていない ⇒ 指令が効いていない

**未検証の対策**
1. 傾きの上限を 8度 → 15度（手動飛行では36度まで使える。8度は控えめすぎた）
2. 目標高度を 0.5m に上げる（**0.15m は地面効果の影響を受ける**。プロペラの風が
   床で跳ね返り、機体を押し回す）
3. 自作ファームを書き込む（LEDを常時明るく、自動着陸を無効化、姿勢オフセットの
   補正、位置指令の直接受付）

## 機材まわりの注意

| 事項 | 内容 |
|---|---|
| USB | OAK-D は USB3 で 37ms、USB2 では 120ms。必ず USB3 に挿す |
| esptool | StampFly も M5GO も 115200 baud。それより速いと失敗する |
| Atom JoyStick | 電源が入っていると 50Hz で arm=0 を送り続け、PC の離陸指令を打ち消す |
| 学内ネットワーク | PlatformIO と Git は `HTTPS_PROXY=http://proxy.okinawa-ct.ac.jp:8080` が必要 |
| Git push | 大きなファイルはプロキシで失敗する。`git -c http.version=HTTP/1.1 push` で通る |
| macOS + RealSense | `pyrealsense2` が動かない（`failed to set power state`、sudo では segfault）。OAK-D を使う |
